# TG Exterminatus Bot

Административный Telegram-бот на **aiogram 3** + **Telethon** (MTProto) +
**PostgreSQL**. Отслеживает участников супергруппы и по команде выполняет
массовую "зачистку" чата: банит всех известных боту пользователей (кроме
администраторов), удаляет форумные ветки (кроме текущей и General) и
создаёт заменяющие. Плюс базовая статистика и ручная синхронизация
участников через userbot-аккаунт.

## Функционал

| Команда | Кто может | Что делает |
|---|---|---|
| `/fire_exterminatus` | любой участник чата* | показывает предупреждение и просит подтверждение |
| `/fire_exterminatus confirm` | любой участник чата* | банит всех известных боту пользователей (кроме админов), удаляет все форумные ветки кроме текущей/General, создаёт заменяющие |
| `/stats` | любой участник чата | показывает реальное число участников (по Telegram) и число отслеженных в БД |
| `/sync` | любой участник чата | принудительно подтягивает полный список участников текущего чата через Telethon-аккаунт |

\* В коде команда **не проверяет права** — считается, что бот стоит только
в приватных/контролируемых чатах. Если нужно ограничить `/fire_exterminatus`
только админами — добавь проверку `utils.is_admin(bot, chat_id, user_id)`
в начало `handlers/ext.py`.

⚠️ **`/fire_exterminatus confirm` — необратимое разрушительное действие.**
Тестируй сначала на отдельном тестовом чате.

## Архитектура

```
bot.py                  — точка входа, регистрирует роутеры
config.py                — читает .env, валидирует обязательные переменные
mtproto.py                — Telethon-клиент (userbot-сессия)
forum_topics.py            — работа с форумными ветками через MTProto
utils.py                    — вспомогательные функции (роли, троттлинг FloodWait)
get_chat_id.py                — utility-скрипт: печатает ID всех групп, где есть userbot

database/
  pool.py                — пул соединений asyncpg к Postgres
  db.py                  — схема БД (таблица seen_users) + CRUD-функции

handlers/
  tracking.py            — молча логирует всех, кто пишет/заходит в чат → seen_users
  stats.py                — /stats, /sync
  ext.py                  — /fire_exterminatus
```

Важно: `tracking.py` не выполняет команд, но **обязателен** — именно он
наполняет таблицу `seen_users`, которую использует `/fire_exterminatus` для
получения списка пользователей на бан. Без него список всегда будет пуст.

## 1. Регистрация бота в Telegram

1. Открой [@BotFather](https://t.me/BotFather)
2. `/newbot` → задай имя и username
3. Сохрани токен (`123456789:AAH...`) — понадобится как `BOT_TOKEN`

## 2. Получение Telegram API_ID / API_HASH (для Telethon)

Часть функционала (`/sync`, удаление/создание форумных веток) работает не
через Bot API, а через MTProto от лица обычного Telegram-аккаунта
("userbot"). Для этого нужны личные API-ключи разработчика:

1. Зайди на [my.telegram.org](https://my.telegram.org) под аккаунтом,
   который будешь использовать как userbot (может быть отдельный аккаунт,
   не обязательно тот же, что владеет ботом)
2. **API development tools** → **Create new application**
3. Заполни форму (значения не проверяются по смыслу):
   - App title — любое, например `tg_bot`
   - Short name — 5-32 латинских символа, уникальное в рамках Telegram
   - Platform — `Desktop`
   - URL и Description можно оставить пустыми/произвольными
4. **Create application** → сохрани `App api_id` (число) и `App api_hash`
   (строка)

⚠️ Эти ключи привязаны к конкретному Telegram-аккаунту. Никому их не
передавай — с ними можно полноценно авторизоваться под этим аккаунтом.

## 3. PostgreSQL

Нужна любая доступная извне Postgres-база. Быстрый вариант — Render:

1. [dashboard.render.com](https://dashboard.render.com) → **New** → **PostgreSQL**
2. Заполни Name, регион — на бесплатном плане (**Free**) база автоматически
   "усыпает"/истекает примерно через 30 дней, для долгосрочного продакшена
   лучше **Starter** и выше
3. После создания открой страницу базы → **Connect** → скопируй
   **External Database URL** (если бот работает не на Render в том же
   регионе) или **Internal Database URL** (если сервис бота и база — в одном
   регионе на Render, это быстрее)
4. Если получаешь ошибку `External traffic not allowed` — зайди в
   **Networking** на странице базы → **Add source** (или в разделе
   **PostgreSQL Inbound IP Rules**) → добавь `0.0.0.0/0` с любым описанием →
   **Save**. Это открывает доступ с любого IP (для более строгой настройки
   впиши конкретный IP/CIDR своего сервера)

**Частая проблема:** локальный интернет-провайдер или мобильный оператор
может блокировать исходящий порт `5432` (нестандартный порт БД). Проверка:

```powershell
# Windows PowerShell
Test-NetConnection -ComputerName <хост_базы> -Port 5432
```

Если `TcpTestSucceeded : False` — порт блокируется на твоей стороне
(файрвол/антивирус/провайдер), а не проблема самой базы. Решения:
подключиться через VPN, либо — лучше — задеплоить самого бота на Render
рядом с базой (см. раздел 6) и использовать Internal URL, который не
зависит от внешних портов вообще.

## 4. Настройка окружения

Склонируй репозиторий и установи зависимости:

```bash
git clone <URL_этого_репозитория>
cd tg-exterminatus-bot-template
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
```

Скопируй `.env.example` в `.env` и заполни:

```bash
cp .env.example .env    # Linux/macOS
copy .env.example .env  # Windows
```

```dotenv
BOT_TOKEN=токен_от_BotFather
DATABASE_URL=postgresql://user:password@host:port/dbname
TELEGRAM_API_ID=число_с_my.telegram.org
TELEGRAM_API_HASH=строка_с_my.telegram.org
MINIAPP_BASE_URL=
```

**Никогда не коммить `.env` в git** — он уже в `.gitignore`, но перепроверь
перед первым коммитом.

## 5. Первый запуск и авторизация userbot-аккаунта

При первом запуске Telethon не имеет сохранённой сессии и запросит вход
**интерактивно в консоли** — номер телефона, код из Telegram, и, если
включена 2FA, облачный пароль. Это нужно сделать **локально**, в терминале
с прямым вводом — не через фоновый процесс/хостинг без TTY.

```bash
python bot.py
```

После успешного входа рядом появится файл `telegram_session.session` —
он хранит авторизацию и позволяет запускать бота дальше уже без повторного
ввода кода. Файл **секретный** (эквивалентен доступу к аккаунту) — не
коммить его в git (уже в `.gitignore`).

Если увидишь в логе `Админ-бот запущен` — всё поднялось успешно.

## 6. Настройка чата в Telegram

1. Добавь бота (не userbot-аккаунт, а именно бота от BotFather) в нужную
   супергруппу
2. Сделай бота администратором с правами как минимум:
   - **Блокировка пользователей** (Ban users)
   - **Управление темами** (Manage topics) — нужно для удаления/создания
     форумных веток в `/fire_exterminatus`
3. Аккаунт-userbot (тот, чьи `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`
   используются) тоже должен состоять в этом чате — иначе `find_chat()` в
   `forum_topics.py` не найдёт его среди диалогов Telethon
4. (Опционально) узнать ID нужных чатов:

```bash
python get_chat_id.py
```

Выведет список всех групп, видимых userbot-аккаунту, с их ID. Эти ID
можно прописать в `SYNC_CHATS` внутри `mtproto.py`, если нужен массовый
`/sync` сразу по нескольким чатам через `sync_all_chats()`.

## 7. Деплой на постоянку (Render — рекомендуемый вариант)

Локальный запуск требует держать терминал открытым постоянно. Для
круглосуточной работы удобнее задеплоить как Background Worker:

1. Запушь код в свой GitHub-репозиторий (без `.env` и `.session`-файлов!)
2. [dashboard.render.com](https://dashboard.render.com) → **New** →
   **Background Worker**
3. Подключи репозиторий
4. **Build Command:** `pip install -r requirements.txt`
5. **Start Command:** `python bot.py`
6. В **Environment** добавь все переменные из `.env` (`BOT_TOKEN`,
   `DATABASE_URL`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`)
7. Если база тоже на Render и в том же регионе — используй **Internal
   Database URL** для `DATABASE_URL`, это быстрее и не зависит от
   блокировок портов

⚠️ **Про Telethon-сессию на хостинге:** background worker не даёт
интерактивный терминал для первого входа (шаг 5). Пройди авторизацию
**локально** сначала — получишь `telegram_session.session` — а затем
либо закоммить этот файл во внутренний/приватный репозиторий (не самый
безопасный вариант, но рабочий), либо загрузи его в Persistent Disk
хостинга, либо ищи механизм ручной загрузки файла в Shell сервиса, если
план это поддерживает.

## 8. Частые проблемы

| Проблема | Решение |
|---|---|
| `RuntimeError: BOT_TOKEN не найден` | Не создан/не заполнен `.env`, либо бот запущен не из той папки |
| `TimeoutError` при подключении к БД | Проверь `Test-NetConnection <host> -Port 5432` — вероятно блокируется провайдером/файрволом, см. раздел 3 |
| `External traffic not allowed` на странице Render Postgres | Добавь `0.0.0.0/0` в Networking → PostgreSQL Inbound IP Rules этой БД (см. раздел 3, шаг 4) |
| При `/fire_exterminatus confirm` никого не банит | Скорее всего пуста таблица `seen_users` — проверь, что `handlers/tracking.py` подключён в `bot.py` и что бот какое-то время находился в чате до запуска команды |
| `forum_topics.find_chat()` кидает `ValueError: Чат не найден` | Userbot-аккаунт (Telethon) не состоит в этом чате — добавь его туда |
| Telethon просит код повторно при каждом запуске | `telegram_session.session` не сохраняется между запусками (например, стёрт вручную или хостинг без persistent-диска) |
| `ModuleNotFoundError` | Не выполнен `pip install -r requirements.txt` в активном venv |

## Безопасность

- `BOT_TOKEN`, `DATABASE_URL`, `TELEGRAM_API_ID/HASH`, `telegram_session.session`
  — всё это эквивалент паролей. Никогда не публикуй их в открытых чатах,
  скриншотах или публичных репозиториях.
- Если случайно засветил токен/ключи где-либо — перевыпусти их (для бота —
  `/revoke` у BotFather, для Telegram API — пересоздай приложение на
  my.telegram.org) как можно скорее.
